# コールセンター稼働最適化アプリ（ローカルLAN試作版）

外部データベース不要、Python標準ライブラリ + SQLiteで動作するLAN内Webアプリです。Node.js、npm、PostgreSQL、Dockerは必要ありません。

## このアプリに含まれる機能

- 管理者・オペレーターのログインと役割分離
- パスワードのPBKDF2ハッシュ保存、強度ルール（8〜16文字・大文字/小文字/数字/記号の4種類のうち3種類以上）、パスワード変更時の表示/非表示切り替え
- オペレーター登録・無効化、対応可能スキル・勤務時間の設定
- スキル別・時間帯別の最低稼働人数設定
- SQLiteによるデータ永続化
- SSEによる更新通知とブラウザの自動再接続
- 10分単位の休憩・スキル配置案の生成
- 最低稼働人数が不足する案は警告付きの下書きとして表示し、管理者が2段階確認した場合に限り例外確定可能（通常確定とは監査ログを分離）
- 管理者による案の確定、オペレーターは確定済みの自分の予定のみ閲覧
- 操作履歴
- SQLiteバックアップのダウンロードと、検証後の復元
- 標準ライブラリだけを使ったスモークテストとHTTP統合テスト

## 重要な制限事項

これは動作する初期プロトタイプであり、実運用可能な完成版とはまだ言えません。特に次の機能は追加・検証が必要です。

- 配置最適化は10分単位のヒューリスティックであり、数学的な最適解や全ケースでの実行可能性を保証しません
- フルスキル担当者の手動固定・割当変更UIは未実装
- 休憩時間帯や勤務ルールを管理者が柔軟に設定する機能は未実装
- オペレーターの既存情報・スキルを編集する機能は実装済み（登録・編集・無効化・再有効化に対応）
- スケジュールの履歴閲覧・差分表示・確定解除は未実装
- TLS/HTTPSの自動設定、アカウントロック、CSRF対策など、本番運用向けのセキュリティ強化は未完了
- 管理者PCの故障・紛失に備えたバックアップ先の自動管理は未実装
- 本成果物はWindows向けのビルド手順を含みますが、Windows用EXE自体はこの作業環境ではビルド・実機検証できていません

本番業務に導入する前に、実際の勤務時間・休憩ルール・最低稼働人数を使った受入テストを行い、最適化結果を人間が確認する運用にしてください。

## 起動（Python 3.10以上）

1. WindowsにPython 3.10以上をインストールし、インストール時に「Add Python to PATH」を有効にします。
2. `start_server.bat` をダブルクリックします。
3. 管理者PCで `http://127.0.0.1:8765` を開きます。
4. LAN内の別PCから `http://管理者PCのIPアドレス:8765` を開きます。
5. WindowsファイアウォールでTCP 8765をプライベートネットワーク内だけ許可します。

Python以外の実行時パッケージは不要です。初回起動時に `data/callcenter.sqlite3` が自動作成されます。

## Windows用EXEのビルド

Windows開発PCで `build_windows_exe.bat` を実行してください。PyInstallerを取得して `dist\CallCenterLocal.exe` を作成します。ビルドにはインターネット接続が必要です。作成したEXEは、Pythonをインストールしていない管理者PCでも起動できる想定ですが、職場のWindows PCで実際に確認してください。

EXE版のデータ保存先は `%LOCALAPPDATA%\CallCenterLocal\data` です。ソース実行時のデータ保存先はプロジェクト内の `data` フォルダーです。

## 初期アカウント

- 管理者：`admin` / `ChangeMe123!`
- サンプルオペレーター：`operator1`〜`operator6` / `Welcome123!`

初回ログイン後、アカウント・保全の欄からパスワードを変更してください。初期ユーザーはデモ用なので、実運用前に必ずサンプルユーザーを無効化または削除し、実際のユーザーを登録してください。

## バックアップと復元

管理者画面の「データをバックアップ」でSQLiteバックアップをダウンロードできます。「バックアップを復元」でバックアップファイルを検証して復元できます。復元は現在のデータを置き換えるため、必ず現在のデータも先にバックアップしてください。バックアップは管理者PC以外の安全な場所にも保管してください。

## テスト

Python 3.10以上で、プロジェクトフォルダー内から次を実行します。

```bash
python tests/smoke_test.py
python tests/integration_test.py
```

テストは認証、ユーザー一覧、サンプルスケジュール生成・確定、バックアップ・復元などを確認します。これらのテストは実際の社内LANやWindows EXEの動作を保証するものではありません。

## データを初期化する場合

サーバーを停止し、データベースをバックアップしたうえで、ソース実行時は `data/callcenter.sqlite3` を削除します。EXE版では `%LOCALAPPDATA%\CallCenterLocal\data\callcenter.sqlite3` を削除します。全ユーザーと設定が初期化されるため注意してください。

## 管理者PCのIPアドレスを確認する方法

1. 管理者PCで `Windowsキー + R` を押します。
2. `cmd` と入力して Enter を押します。
3. 黒いコマンド画面で `ipconfig` と入力して Enter を押します。
4. 有線LANなら「イーサネット アダプター」、Wi-Fiなら「ワイヤレス LAN アダプター Wi-Fi」を探します。
5. その中の「IPv4 アドレス」を確認します。例：`192.168.1.25`
6. オペレーターPCのブラウザで `http://192.168.1.25:8765` のようにアクセスします（IPは例なので、実際に表示されたものを使ってください）。

管理者PCとクライアントPCは同じ社内LANに接続されている必要があります。IPアドレスが変わると接続先も変わる場合があります。継続運用では、社内ネットワーク管理者にDHCP予約または固定IPの設定を相談してください。

## 管理画面の編集・削除と10分刻みの時刻

- 「最低稼働人数」一覧から各設定を編集・削除できます。編集時は対象行の「編集」を押し、フォームで変更後に「変更を保存」を押してください。
- 「オペレーター管理」一覧からユーザー名、表示名、対応スキル、勤務時間を編集できます。編集時にパスワード欄を空欄にするとパスワードは変更されません。パスワードも変更する場合は8〜16文字で、大文字・小文字・数字・記号の4種類のうち3種類以上を含めてください。入力欄の「表示」ボタンで入力内容を確認できます。
- オペレーターの「削除」は、操作履歴や過去のスケジュールを保持するため、完全消去ではなくアカウントの無効化です。無効化したユーザーは「再有効化」で戻せます。
- 勤務開始・終了と最低稼働人数の開始・終了時刻は、00分から50分まで10分刻みのプルダウンです。
- 時刻変更を反映するには、サーバーを再起動し、ブラウザを再読み込みしてください。


## 当日の出勤確認（更新版）

1. 管理者でログインし、「休憩・配置計画」を開きます。
2. 対象日を選択すると「当日の出勤確認」にオペレーター一覧が表示されます。
3. 出勤する人はチェックを付け、欠勤する人はチェックを外します。初めて設定する日は全員出勤として表示されます。
4. 「出勤状況を保存」を押してから「配置案を生成」を押してください。
5. チェックが外れているオペレーターは、その日の休憩・担当配置案の計算対象から除外され、結果に欠勤者として表示されます。

休憩表示は「午前休憩」「昼休憩」「午後休憩」と日本語で表示されます。出勤状況は日付ごとにSQLiteへ保存され、同じ日付を再度選ぶと保存内容が読み込まれます。

## 手動で休憩時間を設定して配置案を作成

管理者は「休憩・配置計画」の「休憩時刻を手動で設定」から、出勤者ごとに午前・昼・午後の休憩開始時刻を選べます。

- 午前休憩：09:30〜11:20の間で開始（10分）
- 昼休憩：11:30〜13:00の間で開始（60分）
- 午後休憩：14:00〜16:20の間で開始（10分）
- 時刻はすべて10分刻みです。勤務時間外や同一オペレーターの休憩重複は拒否されます。
- 「手動設定から配置案を作成」を押すと、サーバー側で休憩時刻・勤務時間のルールを検証し、各時間帯のスキル別最低稼働人数を確認します。
- 休憩枠・勤務時間のルール違反は拒否されます。最低稼働人数だけが不足する場合は、警告付きの下書きとして表示します。
- 警告付きの案を確定する場合、管理者は1回目の確認後、2回目の確認を明示的に承認する必要があります。2段階目だけを直接呼び出して確定することはできません。
- 例外確定では、確認者・確認日時・不足内容を記録し、オペレーター画面へ共有します。警告がない案は通常どおり1回の確認で確定できます。

オペレーター画面の休憩区分も「午前休憩」「昼休憩」「午後休憩」と表示します。


## パスワード設定ルール

管理者・オペレーター共通で、パスワードは8〜16文字です。大文字・小文字・数字・記号の4種類のうち3種類以上を含めてください。ルールは画面だけでなくサーバー側でも検証されます。ログイン、現在のパスワード、新しいパスワード、アカウント登録/変更のパスワード欄に「表示/隠す」ボタンがあります。

## 複数管理者アカウント

管理者でログインし、「オペレーター管理」からアカウントを登録する際に「アカウント権限」を選択できます。「管理者権限も付与」を選ぶと、そのアカウントも管理者としてログインでき、管理者向け設定・アカウント管理・休憩配置の確定を行えます。通常のオペレーターは「オペレーター権限のみ」を選択してください。管理者権限は信頼できる担当者にのみ付与してください。
