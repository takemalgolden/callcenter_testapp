# コールセンター休憩提案・配置管理アプリ — ver1.1形式／休憩専用＋勤務パターン管理版（早番11:30順序修正版／2026-10-13）

このパッケージは、提供された `callcenter_testapp-callcenter_testapp_ver1.1.zip` の**単体構成・フォルダ名・起動バッチ・ポート8765**を基本的に維持しつつ、最新の休憩ルールを組み込んだものです。

**シフト作成アプリ、月間自動シフト生成、希望休管理、シフト確定連携は含みません。** 管理者が手動で定義する**勤務パターン登録・割当**だけを追加しました。 休憩配置に必要な「オペレーターの登録勤務時間」「早番／中番／遅番などの区分」「出勤チェック」は引き続き利用します。従業員の勤務日や開始・終了時刻を月間で自動決定する機能はありません。

## 起動方法 — Windows 10/11

元のZIPにあった `build/` と `dist/` はフォルダとして残しています。ただし元の `dist/CallCenterLocal.exe` は**旧コードのEXE**であり、変更が反映されないため含めていません。Windows上で**必ず新しくビルド**してください。

1. ZIPをすべて展開する。
2. ビルド作業用Windows PCに Python 3.10以上を準備する（ビルド時のみ）。インターネット接続が必要。
3. `build_windows_exe.bat` を実行。`dist/CallCenterLocal.exe` が作られる。
4. 管理者PCで `start_server.bat` を実行。管理者PCではビルド済みEXEさえあればPython不要。
5. 管理者PCのブラウザで `http://127.0.0.1:8765/` にアクセス。ほかの社内PCからは、ネットワークの名前解決が有効な場合 `http://管理者PC名:8765/` にアクセス。
6. 運用中は管理者PCとサーバーを起動したままにしてください。停止は `stop_server.bat` またはコンソール上でCtrl+C。

`CALLCENTER_PORT` 環境変数で待ち受けポートを変えられます。添付いただいたver1.1と合わせて標準値は **8765** のままです。以前の5050番ポートで動かす場合は、管理者PCで `set CALLCENTER_PORT=5050` と指定したコンソールからEXEを起動するなどの設定が必要です。

社内LANの受信ファイアウォール設定は、会社のIT担当者の許可を得たうえで `setup_firewall_lan_only.bat` を管理者権限で使用してください。これはポート8765用です。PC名はIPアドレスの表示を避ける手段であり、IP自体を完全に秘匿するものではありません。

### ソースから起動する場合

Python 3.10以上でプロジェクトフォルダから `python server.py`。標準ライブラリのみで動作し、データベースサーバーやOR-Toolsは必要ありません。`flexible_optimizer.py` は同梱されています。

## 追加機能：勤務パターン登録・オペレーターへの割当

管理者メニューに **「勤務パターン」** タブを追加しました。

1. 管理者でログインし、「勤務パターン」タブを開く。
2. パターン名（例：早番A）、勤務開始、勤務終了、勤務区分（早番／中番／遅番／その他／自動判定）を登録する。開始・終了は10分刻みで編集できます。
3. 「オペレーター管理」→アカウント登録／編集フォームの **「勤務パターン」** で登録済みのパターンを選ぶ。開始・終了・区分が自動入力され、パターン割当中はこの3項目を個別編集できません。
4. 登録／変更保存を押す。登録済み一覧には使用中パターン名も表示します。
5. 固有の時間を指定する場合は「指定なし（勤務時刻を個別入力）」を選ぶと、開始・終了・区分を手動編集できます。

登録済みパターンの名前・時間・勤務区分は編集／削除できます。時間や区分の編集は**割当済みのオペレーター全員に自動反映**されます。削除は割当を解除するだけで、各オペレーターに最後に反映された勤務時刻と区分を残します。削除前に割当人数を確認するダイアログが出ます。

**既に作成・確定した休憩案は自動再計算されません。** 勤務パターンや割当を変えた日は、「休憩・配置計画」から案を再生成して確認・確定してください。これは**日常の勤務時間テンプレート**であり、月間シフトの自動作成・希望休の収集・日別の勤務パターン自動切替は行いません。

**ログイン画面のオペレーター新規登録申請では勤務開始・終了・勤務区分は入力しません。** 登録申請ではID・表示名・パスワード・対応スキルのみ入力し、管理者承認まで無効なアカウントとなります。申請時の勤務時間は内部的に仮値（09:00〜18:00、自動判定）で保存されます。管理者は**有効化して出勤・休憩配置に使う前に**、オペレーター管理で実際の勤務パターンを割り当てるか、正しい勤務時間を個別設定してください。CSV／Excel一括登録はこれまでどおり勤務時間を入力します。

## 休憩ルール

| 勤務の長さ | 自動的に必要になる休憩 |
|---|---|
| 6時間未満 | 前半の10分休憩 × 1回 |
| 6時間ちょうど | 前半・後半の10分休憩 × 各1回 |
| **6時間を超える場合** | **60分の昼休憩 × 1回と、前半・後半の10分休憩 × 各1回** |

- 昼休憩の開始可能時刻は **11:30〜18:50**（10分刻み）。昼休憩は勤務終了までに終わらせる必要があります。
- **早番**：昼休憩の開始可能範囲は **11:30〜14:00**。**昼休憩を11:30に開始する場合は、必ず「昼休憩（11:30〜12:30）→前半10分休憩（12:50以降）→後半10分休憩」の順**に配置します。11:40以降に開始する場合は従来どおり前半10分休憩→昼休憩→後半10分休憩です。自動提案だけでなく管理者の手動変更にも適用します。
- **中番**：前半10分休憩 → 昼休憩 → 後半10分休憩の順序が必須。昼休憩は始業から2時間10分後〜4時間40分後を目安とします。
- **遅番**：始業から2時間10分後〜4時間40分後を目安に昼休憩を配置。昼休憩を前半10分休憩より先にしても構いません。
- **その他**：上記の短時間勤務ルールを適用。6時間超なら昼休憩も必要です。昼休憩範囲は中番・遅番と同じ相対時間帯を使用しますが、昼休憩先行の特例はありません。
- 昼休憩・10分休憩の間は **20分以上** 離します。休憩時間が重複する案、勤務時間外の案、必要休憩が不足する案は確定できません。
- 画面で「自動判定」を選ぶと、始業時間から早番／中番／遅番を推定します。誤判定の可能性があるため、管理者は登録画面で「早番」「中番」「遅番」「その他」を明示的に選択できます。
- 例：9:20〜18:20の早番は11:30〜14:00開始、11:00〜20:00の中番は13:10〜15:40開始、14:00〜23:00の遅番は16:10〜18:40開始の候補を表示します。

勤務時間内に必須の休憩がすべて配置できない場合は、エラーとして案を保存しません。必要人数が不足する場合は警告付き下書きとし、管理者による二段階の例外確定を認めます。**人員不足の例外承認は休憩ルールの免除ではありません。**

## 維持した機能

- 管理者／オペレーター権限、複数管理者、セルフ登録申請（管理者承認まで無効）
- アカウント登録・編集・無効化・再有効化、PW再設定、パスワード強度検査
- 対応スキル Consumer／Merchant／PP、スキル別・時間帯別の必要人数設定
- CSV／Excelによる従業員の一括登録（従業員の勤務区分は初期状態で自動判定）
- 管理者による勤務パターンの登録／編集／削除、オペレーターへの割当・解除（今回追加）
- 日付指定での当日出勤チェック、10分刻みの休憩自動提案、休憩時刻手動調整
- 9:20〜23:00までの時間帯別受電可能スキルの表示と不足警告
- 管理者の確定、オペレーターへの確定済み休憩案の表示、操作履歴
- SQLiteのバックアップ・復元、社内LANのWeb画面

**注意：** 1人の複数対応スキルをそれぞれのキューに表示しますが、1人が同時に複数通話に対応できるとは扱いません。必要人数を独立した担当人数で満たせない場合は「同時着信の実人数」不足を別に警告します。

## データの保存と引き継ぎ

- EXE実行時：`%LOCALAPPDATA%\CallCenterLocal\data\callcenter.sqlite3`
- ソース起動時：同梱フォルダ内の `data/callcenter.sqlite3`

更新時は必ずサーバーを停止し、既存のSQLiteファイルを別の場所へバックアップしてください。前のver1.1で保存したオペレーター・必要人数・出勤データは引き続き利用できます。`shift_type` 列に加えて、今回の更新で `work_patterns` テーブルと `users.work_pattern_id` 列が起動時に自動追加されます。既存オペレーターは初期状態で「指定なし（個別入力）」です。旧ルールの確定前休憩案は新しい条件に合わない場合、確定を拒否します。新しいルールで作り直してください。

**旧統合シフト管理アプリのデータは自動で読み込みません。** 既存の統合アプリ側DBをこのアプリのDBに直接上書きすることは推奨しません。
